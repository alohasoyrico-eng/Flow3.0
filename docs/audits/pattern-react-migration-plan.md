## Non-Negotiable Migration Rules

- A pattern React implementation must compose existing Flow React components; it must not recreate Button, Dialog, Drawer, Input, Menu, Search, Table, Toast, Tooltip, or related visuals internally.
- A pattern must declare foundations and primitives explicitly before implementation. Inferred dependencies are planning evidence, not a contract.
- A pattern that crosses another pattern must expose a composition boundary or runtime slot according to the audit. Boundary-only dependencies must remain documented handoffs unless React actually imports and composes the dependency.
- A template-facing pattern may be consumed by templates, but template-specific layout, copy, and business policy stay in templates. Reusable interaction structure stays in Flow patterns.
- FlowDocs remains a consumer. Pattern behavior, CSS roots, props, accessibility, state contracts, and cascade rules live in Flow artifacts and React package code.
- Structural grouping, background, density cascade, elevation/radius coordination, and non-product surface state resolve through the Surface primitive. Card is allowed only when the formal component contract calls for a card-like content unit; Card must not become a generic group wrapper.
